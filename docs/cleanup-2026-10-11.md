# Application structure and navigation cleanup — October 11, 2026

This pass reorganizes the existing local AICD application. It does not implement Google sign-in, automatic Gmail synchronization, automatic Kimi extraction, sender-question generation, regulations, or a real ECUS connection.

## Navigation

- Shipments is the default destination; Settings is the other main destination. Settings contains only Gmail and ECUS connection cards. Account, team, default-reviewer, regulations and practice-data controls have been removed from Settings.
- Active, Needs review, Issues resolved and Archive are filters in one shipment list.
- Search and filter state are retained when opening a shipment and returning.
- Review & draft, Documents and Messages are the three primary shipment sections.
- Commercial document facts and goods review remain accessible within Review & draft.
- Reports and history are secondary dialogs/actions. Completion and ECUS simulation tools are collapsed.
- Messages shows imported shipment-linked emails and accurately labels the absent Gmail/send integration.
- Removed the VNACCS coverage screen and ordinary AI settings card. The declaration field registry remains internal.
- Vietnamese and English labels remain available, including accessible names for collapsed sidebar controls.

## Source cleanup

The screen is divided into `components/workspace` feature components. `hooks/use-workspace-session.ts` centralizes workspace loading, serialized mutations, revision conflict handling and request feedback. The parent retains selected shipment, queue context and pending edits. Shared UI presentation helpers live in `components/workspace/shared.tsx`; shipment dialogs and the application shell have their own modules.

Removed the unused template component collection, mobile hook, class-name helper, starter database examples and unused starter assets. Removed `.openai`, the Sites Worker/plugin, ChatGPT login bridge, simulated login, generic connector-preview support and obsolete environment/install wrappers. Removed 21 direct dependencies and updated the npm lockfile. Application and refactored feature files are formatted for reading.

`build/worker.ts`, `scripts/runtime-env.mjs` and the simplified Vite config now own the runtime. `npm run dev` uses the same safe local launcher as `npm run local`. Generic builds deny data access without explicit authentication configuration. The retained standalone Supabase adapter still verifies identity and workspace membership.

The local actor, database ID/name, bucket name and `.aicd-local/state` path are unchanged. No migration alters shipment records. Old generated runtime settings are recoverably archived under ignored `outputs/archive/2026-10-11-runtime-cleanup`; customer data and originals are not moved or deleted. TypeScript build cache now belongs under ignored `.next/cache`, not tracked application source.
